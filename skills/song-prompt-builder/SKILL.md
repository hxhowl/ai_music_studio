# 歌曲生成提示词构建

## 核心认知

**Suno 和秒响要的不是同一种东西。** 同一首歌，在两个平台的提示词形态完全不同，不能互译。

| | **Suno** | **秒响 Sway** |
| --- | --- | --- |
| 形态 | 逗号分隔的**英文标签串** | **中文长句**自然语言描述 |
| 优化目标 | 标签密度 + 互斥性 | 人声细节 + 演唱处理 + 段落指令 |
| 长度 | Style 字段 ≤ 200 字符，≤ 15 个标签 | 不限，越具体越稳 |
| 人声 | `female alto, breathy, near-spoken` | "成年女声，气声为主，咬字轻，句尾收音干净" |
| 结构 | 靠歌词里的 `[Chorus]` 等标签 | 提示词里可直接描述段落安排 |
| 负面 | `Exclude Styles` 字段 | 中文里写"不要 XX" |

> ⚠️ 把英文标签直译成中文丢给秒响 → 塌。把秒响长句压成标签塞给 Suno → 糊。各写各的。

---

## 流程

### 第 1 步：九维定参

**九维表见 `references/production-params.md`（唯一事实源，本文件不存副本）。**
逐项定下来，用户没说的给**推荐值并标注**，不要留空。

最易漏的三处：⑦ 质感（必填）、⑧ 编曲事件（必填）、⑥ 人声必须音区 + 音色 + 唱法三件齐全。

### 第 1.5 步：反套路红线（差异化硬约束）

**同质化的根因是"安全词组合"**——`dreamy ethereal melancholic` 这类词被用烂，模型响应已收敛到平均值。写进去等于没写。

定完九维后，逐条自查。细则与替换词表见 **`skills/production-antislop/SKILL.md`**。

| # | 红线 | 要求 |
| --- | --- | --- |
| 1 | **去安全词** | 裸情绪词 ≤ 2 个，且带场景限定；`dreamy` `ethereal` **`melancholic`** `beautiful` `emotional` `catchy` 等黑名单词汇必须替换（完整清单见 `references/production-lexicon.md` 第一节，本表不存副本） |
| 2 | **有事件** | ≥ 1 条时间轴指令。**Suno 用歌词结构标签承载，秒响直接写长句**——不要把长句塞进 Suno 的 Style 字段 |
| 3 | **有锚点** | ≥ 1 个专属锚点：反差音色 / 演奏法器材 / 质感设定，三选一（反差最强）；**只加一件，并说明它出现在哪一段** |
| 4 | **有质感** | ⑦ 必填，年代 / 录音方式 / 空间至少两项 |
| 5 | **乐器带演奏法** | 不出现裸类别名（`piano` `drums` `strings` 单独出现即为不合格） |
| 6 | **Exclude 有针对性** | 排除的是"这个风格最可能的失败形态"，不是随便写几个 |

> **判据**：这串标签里有没有**只有这首歌才会用**的？一个都没有，就是还没做完这一步。
> ⚠️ 不要用"换掉它歌会不同吗"来判断——**你没有听觉输入**，那是编造听感。

### 第 2 步：写 Suno 版

**形态**：英文标签串，逗号分隔。

```
{主风格}, {辅助风格}, {情绪1}, {情绪2}, {人声性别} vocals, {音色},
{乐器1}, {乐器2}, {乐器3}, {BPM} BPM, {质感}, {年代/地域}
```

**硬约束**：
- ≤ 15 个标签
- ≤ 200 字符（Style of Music 字段上限约 200）
- 主风格**唯一**，辅助风格最多 1 个
- 乐器 3–5 件，**每件带演奏法或器材**（`brush snare` 而非 `drums`）
- **禁用歌手姓名**代替风格（写"中国风 + R&B + 说唱段落"，不写"像周杰伦"）
- 纯音乐就显式写 `instrumental, no vocals`
- **质感标签必给**（年代 / 录音方式 / 空间，至少两项）

**必给 Exclude Styles**：把不想要的东西写进排除字段，比在正向里堆词有效得多。
要排除的是**这个风格最可能的失败形态**（古风 → `no operatic vocal, no heavy reverb`；抒情 → `no autotune`）。

**编曲事件怎么落**：Style 字段写不下长句，事件分三处承载——

| 载体 | 写法 |
| --- | --- |
| Style 字段 | 只放**动态词**：`sparse intro` `building` `dynamic contrast` `breakdown` |
| **歌词结构标签（主）** | 这才是事件真正的落点：`[Instrumental Break]` `[Breakdown]` `[Drop]` `[Guitar Solo]` `[whisper]` `[falsetto]` |
| 元标签 `[Style: ...]` | 补充载体，写在歌词开头；主用上面两种 |

> ⚠️ 把"副歌前抽掉鼓"写进 Style 字段 → Suno 读不懂。正确写法：Style 给 `dynamic contrast`，歌词里插 `[Breakdown]`。

**事件落在歌词标签上，但你不能改歌词**（改词是角色一的事）。做法分两种：

| 情况 | 你做什么 |
| --- | --- |
| **已有歌词** | 指出**该在第几段之后插哪个标签**，交给角色一/用户去加。**不要自己改写歌词文件。** |
| **只有风格方向，还没有歌词** | 把标签作为**交付建议**给出（"出词时在副歌前插 `[Breakdown]`"），并说明理由 |

> ⚠️ 不要为了"让事件有地方落"而凭空编一段歌词——那越界了。

**结构标签的完整表**在 `references/suno-tags.md` 第一节（唯一事实源）。
注意：`[Breakdown]` `[Drop]` `[falsetto]` 这些**事件标签**不在歌词侧那两条精简清单里，
插入它们属于**加事件**，要在交付里说明，别默认歌词已经有。

完整标签库见 **`references/suno-tags.md`**；演奏法、质感、反差配方见 **`references/production-lexicon.md`**。

### 第 3 步：写秒响版

**形态**：中文长句，像给一个真人歌手 + 编曲写 brief。

**九要素清单**：见 **`references/platform-miaoxiang.md` 第二节**（唯一事实源，本文件不存副本）。
至少覆盖 **7 项**，缺项必须说明原因。

**写法要点**：
- 用**逗号/分号**分隔要素，形成一整段，不要分点列条
- 人声部分写得越细越好（这是秒响相对 Suno 的优势区）
- 可以直接给**旋律走向**与**句尾处理**这类微观指令
- 不想要的直接写"不要 XX"
- **时间轴指令直接写中文**，这是秒响相对 Suno 最大的优势："前 12 秒纯电钢琴""桥段抽掉鼓留 4 秒纯人声"
- **质感必须具体到录制方式**：不写"温暖"，写"单支铝带麦克风同期录制，70 年代磁带饱和"

完整规范与示例见 **`references/platform-miaoxiang.md`**；事件句库见 **`references/production-lexicon.md`** 第五节。

### 第 4 步：双语输出

每个平台**各出中文 + 英文**两份，共 4 段：

1. Suno · 英文标签串（可直接粘贴）
2. Suno · 中文对照说明（解释每个标签在干什么）
3. 秒响 · 中文长句（可直接粘贴）
4. 秒响 · English 对照说明

**关键**：中文说明 ≠ 把英文翻译成中文。它是**给用户的解释**，说清设计意图。

### 第 5 步：附设计说明 + 待确认项

- 九维定参表
- **专属锚点说明**：写明"这首歌区别于同类的是什么"（哪个反差音色 / 哪条编曲事件）
- 标出 1–2 个"最需要试听后确认"的点（通常是 BPM 和人声音色）

## 常见失败与处方

| 症状 | 诊断 | 处方 |
| --- | --- | --- |
| 太素 | 乐器少 / 情绪词笼统 | 加 1–2 件色彩乐器；"清冷"→"凌晨空旷地铁站的清冷" |
| 风格乱 | 标签过多、主风格不唯一 | 砍到 1 主 + 1 辅 |
| 人声出戏 | 缺语言与音色 | 补"普通话、女声、气声、中低音区" |
| 速度不对 | 没写 BPM | 显式给 BPM + 律动描述 |
| 副歌不炸 | 缺能量对比 | Style 给 `dynamic contrast` + `sparse intro`；主歌与副歌的差异落在**歌词结构标签**（`[Verse]` / `[Chorus]` / `[Breakdown]`）——Suno 的 Style 是单一字段，不支持段落级标签 |
| 意外出现人声 | 没声明纯音乐 | 写 `instrumental, no vocals` |
| **都一个样** | 安全词组合、无专属锚点 | 走 `production-antislop`：加反差音色 / 编曲事件 / 具体质感 |
| **事件没生效** | 长句塞进了 Suno Style 字段 | Suno 读不懂长句 → 落歌词结构标签 `[Breakdown]`，Style 里只留 `dynamic contrast` |

**定向调参原则**：只改出问题的那一维，其余不动，方便用户 A/B 对比。

## 交付检查

### 只有这六条是条件 —— 错了就是错

1. **Suno 形态**：逗号分隔、全英文、**≤15 个标签、≤200 字符**（平台限制，超了发不出去）
2. **主风格 1 个 + 辅助 ≤1 个**，无自相矛盾组合（`fast lo-fi` 这种）
3. **乐器 3–5 件，每件带演奏法或器材** —— `piano` `drums` `strings` 单独出现就是错
4. **人声三件套**：音区 + 音色 + **唱法**各一个（闭集见 `references/suno-tags.md` §3）；
   纯音乐则必须显式写 `instrumental, no vocals`
5. **质感 ≥2 项**：年代 / 录音方式 / 空间与介质
6. **Exclude 非空 + 中英双语 4 段**

> 全过就一句话，不要逐条打 `[x]`、不要报分数（`AGENTS.md` 第 7 节「交付形态」）。
> **这六条之外没有门槛。**

### 其余是参考 —— 卡壳时才查，**不设及格线**

> 这些是"好提示词长什么样"，不是"合格的条件"。写顺了不用看。

| 想解决 | 看哪 |
| --- | --- |
| 出来的歌都一个样 / 没特点 | `skills/production-antislop/SKILL.md`（病历本 + 处方，不是及格线） |
| 编曲事件要不要有、落在哪 | 同上法则 2；载体见 `references/suno-tags.md` §1 |
| 专属锚点 | 同上法则 3 |
| 裸情绪词 / 安全词 | `references/production-lexicon.md` 第一节 |
| 秒响写得够不够细 | `references/platform-miaoxiang.md` 第二节（九要素） |
| 反差不反差 | `references/production-lexicon.md` 第四节 |

## 产出落盘

```
outputs/{歌曲名}/{歌曲名}-prompts-v{N}-YYYYMMDD.md
```

- 每首歌一个文件夹，与歌词放同一目录下
- 版本号**独立递增**（不跟歌词走）：调 BPM、换音色、改人声都算新版，歌词没动也算
- 文件头必须写明**对应哪一版歌词**（写完整路径）—— 歌词结构变了（句数 / 段落）才需要新建提示词
- 绝不覆盖旧版；新版本写明改了什么、**没改什么**、上一版路径、为什么这么改
- 范本见 `examples/002-versioning.md`

# 歌曲生成提示词构建

## 核心认知

**Suno 和秒响要的不是同一种东西。** 同一首歌，在两个平台的提示词形态完全不同，不能互译。

| | **Suno** | **秒响 Sway** |
| --- | --- | --- |
| 形态 | 逗号分隔的**英文标签串** | **中文长句**自然语言描述 |
| 优化目标 | 标签密度 + 互斥性 | 人声细节 + 演唱处理 + 段落指令 |
| 长度 | Style 字段 ≤ 1000 字符（V4.5 起） | **≤ 1000 字符，含换行与标点**（写到 800–880 字收手） |
| 人声 | `female alto, breathy, near-spoken` | "成年女声，气声为主，咬字轻，句尾收音干净" |
| 结构 | 靠歌词里的 `[Chorus]` 等标签 | 提示词里可直接描述段落安排 |
| 负面 | `Exclude Styles` 字段 | 中文里写"不要 XX" |

> ⚠️ 把英文标签直译成中文丢给秒响 → 塌。把秒响长句压成标签塞给 Suno → 糊。各写各的。

## 流程

### 第 1 步：九维定参

**九维表见 `references/production-params.md`（唯一事实源，本文件不存副本）。**
逐项定下来，用户没说的给**推荐值并标注**，不要留空。

最易漏的三处：⑦ **质感**（条件，至少两项）、⑥ **人声三件套**（条件，音区+音色+唱法）、
⑧ **编曲事件**（参考，但漏了最容易出罐头歌）。

⚠️ **速度给区间，别给单值**（这一维最容易被写死）：
- 用户给了具体 BPM → 沿用它；可以照写单值，也可以收成 ±3 的小区间
- 用户没说、歌词档只有"慢 / 中 / 快" → 你把它收敛成一个**区间**（`85–92 BPM`），
  **不要挑一个整数**——区间给生成器留调整余地，单值等于替它做了决定
- 你要改速度（用户要求 / 风格需要）→ 在那 5 行里带一句"从 85 换到 120 左右"，
  并**回看句子会不会挤**（快歌句子挤、慢歌句子空）
- ⚠️ **不用重算时长。** 时长不是条件，也影响不到句数——句数是按"说完没有"定的。
  改速度只影响一句能装多少字

### 第 1.5 步：差异化（参考，不是门槛）

**同质化的根因是"安全词组合"**——`dreamy ethereal melancholic` 这类词被用烂，模型响应已收敛到平均值。写进去等于没写。

怎么判断、怎么改：看 **`skills/production-antislop/SKILL.md`**（六条法则 + 病历本 + 处方）。

> ⚠️ **那张表只留在 antislop，本文件不抄。** 同一份内容只写一处。

> **判据**：这串标签里有没有**只有这首歌才会用**的？一个都没有，就是还没做完这一步。
> ⚠️ 不要用"换掉它歌会不同吗"来判断——**你没有听觉输入**，那是编造听感。

### 第 2 步：写 Suno 版

**形态**：英文标签串，逗号分隔。

```
{主风格}, {辅助风格}, {情绪1}, {情绪2}, {人声性别} vocals, {音色},
{乐器1}, {乐器2}, {乐器3}, {BPM 区间}, {质感}, {年代/地域}
```

**这一步要守的**（编号对应 `AGENTS.md` 第 4 节，**以那边为准**）：
- **≤ 1000 字符**（条件 6；V4.5 起，V4 及更早 200）；**主风格放第一个**（越靠前权重越高）
- 实用区间是 **8–15 个标签 / 150–300 字符**——不是平台限制，是经验：超过约 200 字符后，后面的词会稀释前面的
- 主风格**唯一**，辅助风格最多 1 个（条件 7）
- 乐器 3–5 件，**每件带演奏法或器材**（条件 8；`brush snare` 而非 `drums`）
- **人声三件套**：音区 + 音色 + 唱法（条件 9）；纯音乐显式写 `instrumental, no vocals`
- **质感至少两项**：年代 / 录音方式 / 空间与介质（条件 10）
- **Exclude**（参考，不是条件）：写什么见下方"建议给 Exclude"
- 不用歌手姓名代替风格（写"中国风 + R&B + 说唱段落"，不写"像周杰伦"）

**建议给 Exclude Styles**（不是条件）：把不想要的东西写进排除字段，比在正向里堆词有效得多；空着也不会判错。
要排除的是**这个风格最可能的失败形态**（古风 → `operatic vocal, heavy reverb`；抒情 → `autotune`）。

**编曲事件怎么落**：Style 是整首的全局描述，**没有"第几段"这个概念**，事件分三处承载——

| 载体 | 写法 |
| --- | --- |
| Style 字段 | 只放**动态词**：`sparse intro` `building` `dynamic contrast` `breakdown` |
| **歌词结构标签（主）** | 这才是事件真正的落点：`[Instrumental Break]` `[Breakdown]` `[Drop]` `[Guitar Solo]` `[whisper]` `[falsetto]` |
| 元标签 `[Style: ...]` | 补充载体，写在歌词开头；主用上面两种 |

> ⚠️ 把"副歌前抽掉鼓"写进 Style 字段 → 不生效：**Style 是整首的全局描述，没有"第几段"这个概念**。
> 正确写法：Style 给 `dynamic contrast`，歌词里插 `[Breakdown]`。
> 但反过来也别矫枉过正——**描述性短语 Style 是读得懂的**（`close-mic'd and barely above a whisper` 就有效）。

**标签归你加，词归角色一。** 界线只有一条：
**你可以插入 / 移动结构标签（`[Breakdown]` `[End]` `[whisper]`…），不能改动任何一个字。**

| 情况 | 你做什么 |
| --- | --- |
| **已有歌词** | 直接在歌词里加标签，**另存为歌词的新版本**（v+1），在那 5 行里说一句"我在第 N 段后加了 `[Breakdown]`" |
| **只有风格方向，还没有歌词** | 把标签作为**交付建议**交给角色一（"出词时在副歌前插 `[Breakdown]`"），说明理由 |

> ⚠️ **不要为了"让事件有地方落"而改词、加词、另编一段**——那越界了。
> 加标签会让歌词文件变化，所以**歌词必须出新版本**（条件 1），提示词文件头指向新版。

**结构标签的完整表**在 `references/suno-tags.md` 第一节（唯一事实源）。
`[Breakdown]` `[Drop]` `[falsetto]` 这些**事件标签**不在歌词侧那两条精简清单里，插入即"加事件"；
**结尾要"唱完就收"就加 `[End]` 到最后一行**。它只管"到此为止"，不改变你写的尾奏——
要渐弱，就把渐弱写进尾奏那几句，最后补 `[End]` 收住，两者不冲突。

完整标签库见 **`references/suno-tags.md`**；演奏法、质感、反差配方见 **`references/production-lexicon.md`**。

### 第 3 步：写秒响版

**形态**：中文长句，像给一个真人歌手 + 编曲写 brief。

**九要素清单**：见 **`references/platform-miaoxiang.md` 第四节**（唯一事实源，本文件不存副本）。
**它是查漏清单，不是段落结构**——不要按 1–9 逐项写成九句。

**长度**：上限 1000 字符（**含换行与标点**；写到 800–880 字收手），但**这不是目标**。
一份骨架 170 字符只说得清"哪类歌"；写到 300–500 字符才说清"这一首"。
**别因为怕长而留泛词**（`古风` `深情` `女声`）——预算就是用来消灭这类词的。

**优先级**（`platform-miaoxiang` 第三节有完整表）：
- **必写**：人声身份（性别+年龄+音区+音色）/ 唱法 / 配器+演奏法 / 速度+律动 / **录音质感**（条件 10，两平台都要过）
- **该写**：段落与时间轴 / 风格具体化 / 负面（参考项，字符紧张时它第一个让路）
- **可省**：情绪形容词 / 点缀乐器 / 旋律走向细节 / 完整度声明

**写法要点**：
- **一句一件事**，句号断；同类并列用分号（配器、咬字）；**按主题换行**（唱的人 / 咬字 / 怎么编 / 怎么走 / 质感），不要每项一行
- 人声放最前面，写得最细（这是秒响相对 Suno 的优势区）
- **时间轴直接写中文**，这是秒响最大的优势："前 12 秒纯电钢琴""桥段抽掉鼓留 4 秒纯人声"
- **质感尽量落到录制方式上**：不写"温暖"，写"单支铝带麦克风同期录制，70 年代磁带饱和"
- **段落别写"副歌更炸"**，写成事件：抽掉什么、加什么、留几秒

**交付前数一遍**（条件 6）：**字符数 ≤ 1000（含换行与标点）**。负面是参考，写顺了不必逐条对。

完整规范与示例见 **`references/platform-miaoxiang.md`**；事件句库见 **`references/production-lexicon.md`** 第五节。

### 第 4 步：双语输出

每个平台给**一份可粘贴的实体 + 一行另一语言的说明**：

1. Suno · 英文标签串（可直接粘贴）
2. Suno · **一行**中文说明（选了什么、为什么）
3. 秒响 · 中文长句（可直接粘贴）
4. 秒响 · **一行**English 说明

**一行就是一行的意思。** 逐标签解释属于「展开」，用户问了再给（`AGENTS.md` 第 4 节交付形态）。
说明也不是翻译——它说的是设计意图，不是把英文换成中文。

### 第 5 步：交付（只交两样）

**可粘贴的提示词 + ≤5 行话。** 不交定参表、不交逐标签解释、不交"待确认项"。

- 定参表、九维取值 → **被问再给**
- 专属锚点 → 它现在是**参考**（不是条件），有就写进标签里，**不需要单独开一段解释**
- 拿不准的地方不要列成"待确认"，**给倾向**：
  「我倾向 88–94；你要是听着偏快，往下压到 84 就够」——有倾向的拿不准不是推诿，
  把它列成"待你确认"才是（`AGENTS.md` 第 4 节）

## 输出格式（严格遵守）

```markdown
## Suno

**Style of Music（直接粘贴）**
```
city pop, minor key, rainy neon street at midnight, female alto, breathy, near-spoken,
close-mic, Rhodes, muted bass, brush snare, 88-96 BPM, tape saturation, sparse intro, building
```

**Exclude Styles（直接粘贴）**
`autotune, choir, saxophone, four-on-the-floor`

> 一行中文：主风格为什么是它；人声三件套落在哪三个标签上。

---

## 秒响

**直接粘贴**
...（一整段长句）

> One-line English: what the arrangement is doing and why.

---
**一句话**：选了什么、哪里我还不满意。
```

**没有第三节。** 定参表、逐标签解释、"待确认"都不交——被问再给。
整份交付的字数应该和提示词本身差不多，不是它的三倍。

## 常见失败与处方

| 症状 | 诊断 | 处方 |
| --- | --- | --- |
| 太素 | 乐器少 / 情绪词笼统 | 加 1–2 件色彩乐器；"清冷"→"凌晨空旷地铁站的清冷" |
| 风格乱 | 标签过多、主风格不唯一 | 砍到 1 主 + 1 辅 |
| 人声出戏 | 缺语言与音色 | 补"普通话、女声、气声、中低音区" |
| 速度不对 | 没写速度或写成了单值 | 给区间 + 律动描述 |
| 副歌不炸 | 缺能量对比 | Style 给 `dynamic contrast` + `sparse intro`；主歌与副歌的差异落在**歌词结构标签**（`[Verse]` / `[Chorus]` / `[Breakdown]`）——Suno 的 Style 是单一字段，不支持段落级标签 |
| 意外出现人声 | 没声明纯音乐 | 写 `instrumental, no vocals` |
| **都一个样** | 安全词组合、无专属锚点 | 走 `production-antislop`：加反差音色 / 编曲事件 / 具体质感 |
| **事件没生效** | 把"第几段做什么"写进了 Style | Style 没有段落概念 → 事件落歌词结构标签 `[Breakdown]`，Style 里只留 `dynamic contrast` |

**定向调参原则**：只改出问题的那一维，其余不动，方便用户 A/B 对比。

## 交付检查

### 核对 `AGENTS.md` 第 4 节的第 1、6–11 条

本文件**不复述条件内容** —— 条件只写在一处。去读那七条：
**版本化 / 平台长度上限 / 主风格唯一 / 乐器带演奏法 / 人声三件套 / 质感两项 / 双语不互译**。

> 全过就一句话，不逐条打 `[x]`、不报分数。**这些之外没有门槛。**

### 其余是参考 —— 卡壳时才查，**不设及格线**

> 这些是"好提示词长什么样"，不是"合格的条件"。写顺了不用看。

| 想解决 | 看哪 |
| --- | --- |
| 出来的歌都一个样 / 没特点 | `skills/production-antislop/SKILL.md`（病历本 + 处方，不是及格线） |
| 编曲事件要不要有、落在哪 | 同上法则 2；载体见 `references/suno-tags.md` 第一节 |
| 专属锚点 | 同上法则 3 |
| 裸情绪词 / 安全词 | `references/production-lexicon.md` 第一节 |
| 秒响写得够不够细 | `references/platform-miaoxiang.md`（第四节查漏 + 第三节优先级） |
| 反差不反差 | `references/production-lexicon.md` 第四节 |

## 产出落盘

```
outputs/{歌曲名}/{歌曲名}-prompts-v{N}-YYYYMMDD.md
```

- 每首歌一个文件夹，与歌词放同一目录下
- 版本号**独立递增**（不跟歌词走）：调 BPM、换音色、改人声都算新版，歌词没动也算
- 文件头必须写明**对应哪一版歌词**（写完整路径）—— 歌词结构变了（句数 / 段落）才需要新建提示词
- 绝不覆盖旧版；新版本写明改了什么、上一版路径、为什么这么改
- 范本见 `examples/002-versioning.md`
- **顺便**：本轮对话在 `outputs/{歌曲名}/{歌曲名}-log.md` **追加两行**（追加写、不带版本号），
  格式见 `references/logging.md`。不是条件，漏记不判错；**别贴进回复**

# 中文歌词创作

## 铁律

1. **结构标签一律英文**，方括号、独占一行，标签内不写中文。
2. 歌词是**唱**的，不是读的。但**你听不到声音**——所以别用"念一遍顺不顺"来判，
   用可判定的三条查拗口：① 连续同声母字 ② 连续同韵母字 ③ 一句超出一口气（字数按 BPM 算）。
3. 押韵服务于情绪。宁可破韵，不写"我的心/你的人"这种填充句。

## 一、结构标签与模板

### 结构标签

完整标签表（常用度、元标签、演唱指示）见 `references/suno-tags.md` 第一节 —— 唯一来源，不要在这里另存一份。写词只需记住三条：

1. **英文、方括号、独占一行**：`[Intro]` `[Verse]` `[Pre-Chorus]` `[Chorus]` `[Post-Chorus]` `[Bridge]` `[Instrumental Break]` `[Outro]` `[End]`
2. **`[Breakdown]` `[Drop]` `[whisper]` `[falsetto]` 是编曲事件的落点**，不只是结构标记（Suno 的 Style 字段读不懂长句，事件只能落在歌词标签里）
3. **纯器乐段只写标签**，标签后空一行，不写说明文字

### 模板（只取骨架，句数去源头算）

> ⚠️ 这里刻意**不列句数**。句数必须按实际 BPM 现算（见第三节），
> 抄表里的数字是最容易犯的错。完整核算、选型规则与 120 BPM 实测案例见
> **`references/song-structure.md` 第六、七、八节**。

| 模板 | 风格 | 典型 BPM |
| --- | --- | --- |
| T1 | 抒情 ballad | 85 |
| T2 | 紧凑流行 | 95 |
| T3 | 叙事民谣 | 90 |
| T4 | 情绪堆叠（末次副歌加长） | 85 |
| T5 | 短平快（60–90 秒，唯一短模板） | 100 |
| T6 | 说唱主导（主歌是主体） | 90 |
| T7 | 古风长句（2 小节/句） | 90 |
| T8 | 电子舞曲（器乐占比高） | 128 |
| T9 | R&B / Neo-soul（副歌长） | 92 |

**四步收敛，不要挑眼熟的那个**（摆 9 个模板让 AI 挑，它会挑第一个）：

1. **目标时长**：60–90 秒 → 只有 T5；2:00–3:30 → 其余
2. **谁是主体**：副歌是主体（抒情/宣泄）→ T1/T4/T9；主歌是主体（叙事/说唱）→ T3/T6；平衡 → T2；器乐是主体 → T8
3. **副歌几次、要不要变奏**：三次递进 → 6 句；末次要爆发 → 末次加长到 8 句（T4）；只回扣标题 → 4 句
4. **风格特例**：古风长句 → T7；电子舞曲 → T8；R&B → T9；说唱 → T6

**模板给**：有哪些段落、顺序、重复几次；可选段落去留建议；典型 BPM 作默认值。
**模板不给**：句数（随 BPM 变）、BPM（随用户要求变）、全首时长（随实际 BPM 变）。

可选段落不要默认全加：Pre-Chorus 在 T3/T4/T5 可省；Bridge 在 T5/T6 可用器乐间奏代替。
选完的理由**被问到时能说清就行**，不主动交。

## 二、十三辙押韵

完整韵字表见 `references/rhyme-zh.md`。

| 辙名 | 韵母 | 情绪倾向 | 例字 |
| --- | --- | --- | --- |
| 发花 | a ia ua | 明亮、开阔 | 花 家 话 下 沙 芽 霞 |
| 梭波 | o e uo | 沉稳、叙述 | 河 火 我 说 破 过 朵 |
| 乜斜 | ie üe | 婉转、清冷 | 月 雪 夜 谢 别 街 蝶 |
| 一七 | i ü er | 细腻、私密、易密韵 | 期 你 意 里 雨 去 句 |
| 姑苏 | u | 低沉、呜咽 | 路 湖 树 苦 雾 孤 渡 |
| 怀来 | ai uai | 舒展、叹息 | 来 开 海 爱 外 待 快 |
| 灰堆 | ei ui | 柔婉、回落 | 悲 飞 水 泪 回 灰 醉 |
| 遥条 | ao iao | 悠远、飘逸 | 高 老 笑 道 草 桥 照 |
| 由求 | ou iu | 忧郁、绵长 | 愁 秋 留 手 头 酒 旧 |
| 言前 | an ian uan | 开阔、舒展、最常用 | 前 天 年 面 见 远 山 |
| 人辰 | en in un | 深沉、内敛 | 心 深 真 门 春 云 沉 |
| 江阳 | ang iang uang | 昂扬、宏大 | 光 长 方 上 乡 唱 望 |
| 中东 | eng ing ong | 浑厚、共鸣强 | 风 梦 中 空 声 影 情 |

**选韵**：开口度配情绪（激昂用江阳/言前/发花，低回用一七/姑苏/由求）；副歌定死一辙，主歌可换辙制造对比；言前与人辰（-an / -en）可通押但慎用，容易糊；一七辙字多好押但易写得绵软无骨；仄声韵（三四声）比平声更有推进力，说唱和摇滚常用
——但**只对无拖腔的卡点句成立**：凡是句尾拖长音、hook、大跳的位置，回到上一节的倒字判定（优先平声）。
（这就是为什么"一七辙最易也最险"：开口小 + 仄声多，说唱卡点很爽，抒情长音必倒字。）

**韵脚位置**：句尾韵（默认）；句中韵（顿挫处押，增密度，说唱常用）；双押/三押（末尾连续 2–3 字同韵）；转韵（段落切换时换辙，标记情绪转折）。

**押韵密度**（此前没有默认值，实测因此走过两个极端——先 4/6 句押被判"听感接近无韵"，
后改成 6/6 句句押。**现在定死默认值，别再拍脑袋**）：

| 段落 | 默认密度 | 能放开几句 | 放在哪 |
| --- | --- | --- | --- |
| **主歌** | **句句押** | 至多 **1 句** | 只能是**非末句**；末句放开会让整段散掉 |
| **副歌** | **句句押** | **0 句** | 副歌是记忆点，密度不能松 |
| 预副歌 | 句句押 | 1 句 | 末句放开可以做爬升，是常见且有效的处理 |
| 桥段 | 可换辙，密度可松 | 至多 1/3 | 换辙处（换辙本身就是转折信号，不靠密度） |
| 尾奏 | 允许**破韵**收尾 | — | 末句（"周六 不用打卡"这类口语收束） |

- ⚠️ **只有偶数句押韵（6 句押 3 句、押 4 句）在中文里听感接近无韵** —— 中文不是靠重音撑节奏的，
  韵稀了就散。要么句句押，要么明确声明这是叙事民谣/说唱的刻意处理。
- ⚠️ **句句押 ≠ 可以重复同一个韵字。** 但"重韵"要按**听感**判，不按韵书判：

  | 情况 | 判定 |
  | --- | --- |
  | **相邻两句**同字收尾 | **偷懒，必改**——连着两句都落同一个字，听感上立刻暴露 |
  | 隔 2 句以上同字，**且是刻意的呼应** | **是手法，留着**（副歌首尾问答、hook 复沓、顶针） |
  | 隔 2 句以上同字，纯属词穷 | 能听，但优先换同辙另一个字 |
  | 一段内同一个字出现 **≥3 次** | 无论隔多远都显词穷，必改 |

  > 传统韵书里"重韵"指同一韵段内重复用同一个韵字，**不分相邻**——那是填词考试的规矩，
  > 流行歌不套它。听众不会去数一段里有几个"园"，但会立刻听出连续两句都落"园"。
  > 实测例子：副歌「这是不是个动物园／……／这是疯狂的动物园」——同一个"园"字，隔了 3 句，
  > **是首尾问答的结构，不是重韵。别把它改掉。**
- 说唱 / 长句风格可放宽到隔句押——放宽是你的判断，**不用为它写一段说明**。

### 声调与旋律（中文特有的"倒字"）

英文要求重音落在拍上（见 `lyric-en` 的重音对齐），**中文的对应物是声调与旋律走向的冲突**——
同一个字配上不同的旋律走向，会被听成另一个字，这叫"倒字"。

- "我买两支"配下行旋律 → 听成"我卖两只"
- "你好"配上行的两个高音 → 听成"尼蒿"

**四条可执行判定**：

> ⚠️ 本流程是先写词、后出旋律，写词时**通常没有旋律可参照**。
> 所以第 1 条按**位置**执行（不需要旋律），第 2、4 条在**已知旋律 / 有 demo 时**再校一遍。

| 位置 | 要求 | 需要旋律吗 |
| --- | --- | --- |
| **句尾 / hook / 长音处** | 优先平声（一、二声），**避免上声（三声）** —— 三声字在长音上必然被拉成"半上"，最容易听错 | **不需要**（按位置默认执行） |
| **旋律下行处** | 不用去声（四声）收尾 —— 去声本身就是下降的，配下行会加倍下滑 | 需要 |
| **连续两个三声** | 前一字变调读二声，要按**变调后**的读音校验（"老虎"实际唱成"劳虎"） | **不需要** |
| **句内 ≥ 3 个同声母字** | 拗口且听不清（"蜘蛛知足"），换字 | **不需要** |

**与选韵的关系**：这就是"一七辙最易也最险"的深层原因 ——
`i` `ü` 开口度小、仄声字多，既难唱响又容易倒字；
`江阳` `言前` `发花` 开口大、平声字多，**天然抗倒字**，hook 句优先用这几辙。

**检查法**：你读不出声，所以分两条线查——
① **按位置查**（不需要旋律）：句尾 / hook / 长音位是否平声收尾；有无连续两个三声；有无 ≥3 个同声母字；
② **有旋律 / demo 时**再按走向校"下行处不用去声"，没旋律就跳过，不要假装念过。
念到某个字觉得"好像是另一个字"——那就是倒字，换字或改调。

> "顺口"和"不倒字"不是一回事：前者查拗口（同声母/同韵母连排），后者查**字义被听错**。

## 三、句数与时长（**不要一律 4 句**）

给范围不给规则，模型就取最小值 —— 每段 4 句的结果是全首只有 1:51（掉出 2:00 下限），副歌 11 秒就走了，情绪根本堆不起来；而且段落句数全相等，是结构层面的"AI 对称"。**句数是算出来的，不是拍脑袋定的。**

### 决策流程（**写完副歌再回来做这一步**）

> ⚠️ **顺序很重要**：这一节是第四节第 ④ 步的展开。
> **副歌必须先写完**（第四节 ③）——你才知道要写多长、情绪要堆到哪。
> 先算结构再写副歌，就是旧流程的坑：结构对了，但副歌没话说。

所有速查表、模板库、换算表都在 **`references/song-structure.md`**（唯一事实源）。
下表「查哪里」一律指该文件的节号（不是本文件的）。

| 步 | 做什么 | 查 `song-structure.md` |
| --- | --- | --- |
| ① 选模板 | 按四步收敛取 T1–T9，**不要挑眼熟的那个** | 第七节 |
| ② 定 BPM | 用户说了用用户的；没说取模板典型值**并声明** | 第八节 |
| ③ 算句数 | `单句秒数 ≈ 240 ÷ 实际 BPM`；副歌再按情绪功能取下限 | 第二、四节 |
| ④ 校验 | 副歌时长、全首时长、段落句数关系 | 第二、五、八节 |

### 结构上只有一条是条件

`AGENTS.md` 第 7 节第 4 条**结构自洽**：同功能重复段句数相等 + 全首时长 2:00–3:30。

⚠️ 别把它写成"相邻段落句数不要相等"——照那句执行会把 V1、V2 写成不同句数（同旋律，唱不了）。

**其余全是参考**，卡壳时去 `references/song-structure.md` 查。下面几条只是常用提示，**别当门槛**：

- **模板只给骨架**：照抄 T2 副歌 6 句 + 120 BPM 只有 12 秒，会偏短。120 BPM 的常见解是 8 句 + `[Post-Chorus]`
- **副歌 15–22 秒是经验值**（按 85 BPM 量的）。BPM 高时保句数、不保秒数——减句数去凑秒数会伤信息量
- **主歌 / 预副歌 / 副歌句数有差异**更好听；桥段、尾奏不必强行凑差异
- 叙事点缀型副歌可以短到 10 秒，靠出现次数建立记忆
- 长句（古风 / 氛围）一句占 2 小节，句数少、字数多，同样成立

### 单句字数（**参考区间，不是上限**）

| 段落 | 参考字数（85 BPM 基准） |
| --- | --- |
| Verse | 7–11 字 |
| Chorus | 7–12 字 |
| Pre-Chorus | 5–8 字 |
| Bridge | 7–11 字 |
| Outro | 3–7 字 |
| **长句风格**（古风 / 氛围） | **12–16 字**（一句占 2 小节，句数相应减少） |

> ⚠️ **这是参考，不是上限。** 一口气能唱多少取决于旋律、断句、停顿、谁来唱，**±2 字完全正常**。
> **不要为了压字数改掉一个更好的句子。**
> 实测教训：`我说 哥 周一还得交周报`（全首最像真人的一句）就是为压字数 + 凑 AABB 被改成
> `我烦恼 周一汇报还得交` 的——零收益，纯损失，而自检照样判"通过"。
> 只有当一句明显长到念不完（周边 8 字它 16 字）才值得动，动之前先问：**改完是不是更难听了？**
>
> BPM 高时字数自然收紧（120–140 BPM 约 6–9 字），换算表见 `references/song-structure.md` 第二节。
> 但那张表同样是参考——**它给的是"大概写多少舒服"，不是"超了就错"。**

### 中英混写

中文歌里夹英文很常见，但**结构一律按主唱语言算**。

| 问题 | 规则 |
| --- | --- |
| 用哪个 skill | 以**主唱语言**定：中文为主 → 本 skill；英文为主 → `lyric-en` |
| 字数怎么算 | 中文部分按中文字数；**整句英文**按音节算（1 音节 ≈ 1 字估）；**句内混写**（"我按下 play"）中文按字、英文 1 音节 ≈ 1 字，合并计入总长度 |
| 押韵 | 中文部分照十三辙；英文词不进十三辙，可自押，**但不要指望中英互押** |
| 英文放哪 | hook 句、副歌尾句、预副歌的爬升句 —— 位置要**固定并出现 2–3 次**才成立 |
| 可唱性 | 英文部分仍要**重音落拍**（见 `lyric-en` 的重音对齐），否则在中文旋律上会吞字 |

⚠️ 三个坑：
1. **不要整段英文** —— 会破坏中文字数对齐与韵脚密度
2. **不要为了"洋气"加英文** —— 夹的那一句必须是中文说不出来的（语气、节奏或双关），否则是装饰
3. **结构标签不受影响** —— 混写时标签仍然全英文

**对齐只是参考**：同段落对应句字数差太多会唱不顺（大体 ±2 字内舒服），
但**别为了对齐改掉更好的句子**——理由见第三节字数说明。
**长句风格改按总字数看**：副歌 30–60 字 —— 真正的约束是总时长，不是句数。

**被问到时能说清就行**（不要主动交）：选了哪个模板、为什么；实际 BPM 及来源；每段几句、为什么；
BPM 与模板典型值不同时句数做了什么调整。（交付形态见 `AGENTS.md` 第 7 节）

## 四、写作流程

```
⓪ **定场景 + 写那句锚句**（动笔前必做）
   · 场景边界：几点 / 在哪 / 这个人在做什么 / 场景里**实际存在**的物件
     例：不是"孤独"，而是"凌晨 00:47 的末班地铁，车厢里 3 个人，手机 4% 电"
     跳过它，写出来的就是"放之四海皆准"的平均化句子
   · ★ **锚句**：全首最像人说的那一句，先写出来（往往就是歌名）
     ⚠️ 这一句优先级最高（冲突时它赢）。**先有它，才有这首歌。**
     写不出这句，说明你还没找到这首歌——别急着往下走
   · **信息不足怎么办**：**自己给一个具体场景，一句话复述后直接开写**
     （"我先按凌晨末班地铁来写，不对你随时打断"）。
     ⚠️ 不要反复追问，也不要写空泛的——**用户纠正一个具体版本，比面对空白快得多**

① 需求澄清 + 提炼立意
   · **只问无法替他默认的**（语言）；风格/情绪/视角自己给默认值并一句话复述，直接开写
   · 已经说过的不要再问；不要为了走流程凑问题
   · 立意一句话，具体到场景，不是抽象情绪词
   （与 ⓪ 可互换先后，谁先想到都行）

② 定调性：情绪弧线 / 视角与称谓 / 待谁唱 / hook 方向

③ **先写副歌 —— 定靶心**（⚠️ 这一步在写主歌之前）
   用锚句做 hook，把"这首歌要说什么"写清。
   副歌是主歌的答案，**答案要先想清楚，再铺那条通往它的路**。
   ⚠️ 副歌写不出来 = 立意还没想清 → 退回 ⓪，**不要硬写主歌**。
   （先写主歌会怎样：写 V1 时不知道要抵达哪里，于是六个镜头并列——那就是流水账）

④ **定结构（按副歌倒推）**
   模板骨架（T1–T9，**只取骨架**）+ 实际 BPM + 各段句数 + **时长校验**
   —— 一次算完，别留到最后返工。BPM 一变就按实际值重算
   （句数算法、模板见第三节与 `references/song-structure.md`）

⑤ **定韵（允许事后改）**
   看副歌自然落在哪个辙，**优先用它**；写不下去可以换，主歌也可另起一辙
   ⚠️ **不要让韵去决定内容。** 优先级里韵脚低于"唱句顺口"，它不该在动笔前锁死
   （旧流程把选韵放在写词之前且"定死"，这正是"为押韵而押韵"的结构性来源）

⑥ 写主歌 —— **主歌是"怎么走到副歌那句话"的过程**
   先问：从什么状态出发，才能让副歌成立？
   铺陈 = 给画面（具象 + 动作），不抒情；每段要成**一条动作链**，不是镜头清单
   → 预副歌（短句，情绪爬升）→ 桥段（换视角 / 换韵，说一句最真心的话）→ 尾奏（渐弱，留白）

⑦ **删 —— 这一步不是"自检"**
   逐句问：**删掉它，歌更差吗？** 不更差就删。
   最后从头扫一遍：**有哪一句你会想跳过？** 想跳过的那句就是该改的。
   （别写"念一遍""听一遍"——你听不到声音，见铁律 2）
   （不查规则、不打勾——规则是参考，不是交付条件）
```

> **同一步内要取材时**，按 ⓪ 的场景边界去 `lyric-imagery-rhyme` 取意象词组与押韵候选字。

**分工**：主歌 = **给画面**（具象名词 + 动作），不评判；副歌 = **给态度**（抒情 + 重复），是唯一允许直白的地方；桥段 = **给转折**（换个说法说同一件事，或说出主歌副歌都没说的那句）。

**每个后出的主歌都比前一个推进一层**（不只 V2——T3、T6 有三段主歌）：
句数相等（同旋律）不代表内容可以重复。V1 铺场景，V2 就要推进 ——
换时间（"三天后"）、**换观察对象**（V1 写自己的手，V2 写对方的手；
⚠️ 换的是被看的对象，**不是叙述人称**——人称仍通篇统一，见第五节"人称混乱"）、
或让 V1 埋下的物件在 V2 里发生变化（V1 里"手机 4% 电" → V2 里"关机了"）。
⚠️ 只把 V1 换个说法重写一遍，正是 `lyric-naturalness` 诊断表里"后出的主歌推进了一层"要抓的"换个说法重复"。

**hook 怎么造**（不只要有，还要好记、好唱）：

| 要点 | 说明 |
| --- | --- |
| **位置** | 副歌**第一句**（最先被听到），并在副歌末句或 `[Post-Chorus]` 再现，形成闭环 |
| **长度** | **短于周边句** —— 周边是 8 字句时 hook 写 5–6 字，短才易记（**hook 句是"字数差 ≤ 2"的唯一例外**） |
| **开口度** | 优先开口元音（a / ang / an / ao），唱得响；闭口音（i / ü）难唱响且易倒字（见第二节） |
| **重复** | 字面重复 2–3 次，**不做变化**；三次副歌要变就变**第 4 句**（6 句副歌的标准变奏位，见下），不碰 hook |
| **内容** | 就是歌名或歌名的近义句；**不含抽象情绪词**（"会好的"这类不抓耳） |

⚠️ hook 三次都变 = 没有 hook。变奏留给**第 4 句**（6 句副歌的标准变奏位），
不要动第 1–3 句——第 2 句是"展开 hook"，改掉等于把 hook 拆了。
（6 句改 1 句 ≈ 17%，hook 最稳；完整落法见 `references/song-structure.md` 第四节。）

### 冲突时谁让路

写词时形式指标之间、形式指标与质量目标之间一定会打架。**优先级是固定的**：

> **私人口吻 > 唱句顺口 > 韵脚 > 字数对齐**

**不参与排序的条件**（只有这四条，其余都可让）：
结构标签格式、同功能重复段句数相等、全首时长 2:00–3:30、能唱。

⚠️ **「Suno ≤200 字符」不在作词侧**——那是 Style 字段的限制，管的是提示词，不是歌词
（歌词本身没有字符上限）。别把两侧的条件混着算。

⚠️ **"单句字数上限"不在其中**——它是**参考**，不是硬约束。
之前它被写成"无论怎么写都必须满足，没得让"，结果模型一遍遍要求压字数，
把更好的句子改坏了。**为了压字数牺牲句子，是错的。**

| 冲突 | 谁赢 |
| --- | --- |
| 一句"只有他会说"的话，但字数超了 | **话留下**，把周边的句子压缩来腾空间 |
| 一句很顺的话，但不在韵上 | **话留下**，换韵脚字或改周边句去将就它 |
| 韵脚完美但句子别扭 | 韵让路 |
| 字数很齐但读起来假 | 字数对齐让路（毛边本来就是允许的） |

### 不许推诿：必须做出选择

这是"防御性"的第二张脸——**不敢下判断，把决策推回给用户**。

❌ 实测原话（《疯狂动物园》v7）：

> 「两个画面都成立：现在这版更强调"动物在上流社会的休闲"，狮子理发那版更强调"动物在做人的服务业"。**看你想要哪一种。**」
> 「**可留可不留**的两处」

你请它做创作，它给你出选择题。这跟"写一堆说明"是同一个病：**不承担创作责任**。

| 不许写 | 要写 |
| --- | --- |
| 两种都成立，看你想要哪一种 | 我选 A，因为（一句理由） |
| 可留可不留 / 或者也可以 | （直接决定留还是不留） |
| 若想更克制，可换成 X | 已经换成 X（如果真觉得更好）／不提 |

**想给备选，最多一句**：「另一个方向是 X，我选了 Y 因为 Z。」——一句话，然后闭嘴。

⚠️ **改词时，不得为了形式指标改动已经通过自检的"私人口吻"句。**

实测反例（2026-10-31《疯狂动物园》）：v6 的 `我说 哥 周一还得交周报`
被改成 `我烦恼 周一汇报还得交`，理由是凑 Bridge 的 AABB——
**但"报"与"好"同为遥条辙，那一句本来根本不用动。**
结果是全首最像真人的一句被形式指标改坏了，而自检照样判通过。

**要动这种句子，必须在改动对照表里写明"为什么值得"**；写不出理由就别动。

## 五、中文歌词的常见坑

| 坑 | 症状 | 解法 |
| --- | --- | --- |
| 文言倒装 | "繁花落尽处"式生硬 | 改成口语能说的话："花都落完了" |
| 抽象词堆叠 | 孤独、寂寞、忧伤、彷徨连用 | 换成具象：空椅子、未接来电、凉掉的茶 |
| 韵脚陈词 | 心/人/情/梦/痛 反复出现 | 换辙，或用 `lyric-imagery-rhyme` 找同辙的冷门字 |
| 字数失控 | 一句 5 字一句 14 字 | 按 `references/song-structure.md` 第二节的 BPM × 字数表重写（不是固定字数表） |
| 副歌无 hook | 每句都新，没有重复 | 把核心句提到句首并重复 2–3 次 |
| 人称混乱 | 一段"我"一段"你"一段"他" | 通篇统一，桥段才允许切换 |

## 六、自然度红线（创作期预防）

AI 味的病根是"平均化" —— 写出来的东西所有人都能写，那它就谁也不属于。取材阶段就要守住，别等写完再补救。

- **取材三问**：能被镜头拍到吗？换到另一首歌还成立吗？有没有一个细节是别人写不出来的？
- **细节要能被镜头拍到，但不要数个数** —— 凑够三个名词不等于有了画面，凑法见下一条
- ⚠️ **细节成链，不成堆**：每句承接上一句，末句完成一个动作或转折。
  照着"多塞几个具象名词"凑数，凑出来的就是一行一件的分镜表（实测踩过，见 `lyric-naturalness` 法则 1）。
  判据：**抽句测试**（抽掉一句，下一句还接得上吗）与**主语测试**（6 句是否 6 个不相干的主语）
- **留一条线索物**：让同一个物件**再出现一次，且第二次出现时状态变了**（没摘 → 被嚼烂 → 还在）。
  每段换一个新物件，段段合格却没有主线——物件要**承担叙事功能**，不是当装饰
- **有当代生活物件**：电量 12%、外卖备注、已读不回、末班车、快递柜（不是放在 1990 年也成立的那种）
- **通用意象必须加限定**：不写"雨"，写"把伞吹翻的雨"
- **句长要有毛边**：前几句保持对齐，**允许 1 句（通常是段落末句）明显更长或更短**做落句。不要全段等长（假），也不要全段乱（唱不了）
- **情绪越重，用词越轻**：不写"想你想到流泪"，写"牙刷还在杯子里"

替换词查 `references/anti-ai-lexicon.md`；完整法则与改写流程见 `skills/lyric-naturalness/SKILL.md`。

## 七、交付检查

### 核对 `AGENTS.md` 第 7 节的第 1–5 条

本文件**不复述条件内容** —— 以前四份副本各写一份，已经开始漂移。
去读那五条：**版本化 / 结构标签 / 排版 / 结构自洽 / 能唱**。

> 全过就写一句话结论，不罗列、不打分。**这五条之外没有门槛。**

### 下面是诊断表 —— 卡壳时才查，**不是交付门槛**

> 这些是"好歌词长什么样"，**不是"合格歌词的条件"**。
> **写顺了就不用看；只有当你觉得"哪里不对但说不上来"时才来翻。**
> ⚠️ 把它们当门槛，模型就会去凑条件而不是写好歌——这是实测踩过的坑（2026-10-31）。

**整体弧线（怀疑"不成篇"时先查这里）**
- [ ] **叙事线**：全首有一条情感变化轨迹（⚠️ 场景变化 ≠ 情感变化）
- [ ] **句间关系**：抽 3 处相邻句，每处都能说出因果 / 递进 / 转折 / 对比——
      说不出（只能说"都是在描写 X"）就是流水账
- [ ] **副歌的必然性**：副歌是从主歌"逼"出来的，不是换个话题再写一段
- [ ] **每段末句比首句走得更远**（段内也有微弧线）
- [ ] **有一个物件出现 ≥ 2 次且状态发生了变化**（线索物，不是装饰）

**句子质量（怀疑"不像歌词""太散"时查）**
- [ ] 副歌韵辙统一；**押韵密度达标**（主歌至多放开 1 句且不是末句，副歌句句押，见第二节）
- [ ] **重韵按听感判**：相邻两句同字要改；一段内同一个字 ≥3 次要改；
      隔开且刻意的呼应（副歌首尾、hook 复沓）**不算重韵，别改**（见第二节）
- [ ] 同段落对应句字数差 ≤ 2 字
- [ ] **拗口自查**（别写"念一遍顺口"——你读不出声）：连续同声母字、连续同韵母字、
      一句超一口气；无文言倒装、无"为押韵而押韵"的废句
- [ ] **无倒字**：句尾 / hook / 长音位是平声收尾；无连续两个三声；一句内无 ≥3 个同声母字（见第二节）
- [ ] **hook 五条都满足**：在副歌首句、短于周边句、开口元音、字面重复 2–3 次、就是歌名
- [ ] **后出的主歌推进了一层**（换时间 / 换观察对象 / 物件变化），不是换个说法重复
- [ ] 主歌给画面、副歌给态度、桥段给转折

**自然度（怀疑"太 AI 了"时查，第六节）**
- [ ] 每段有能被镜头拍到的细节，**但不数个数**（凑数就会写成报菜名）；抽象情绪词很少
- [ ] **细节成链不成堆** —— 抽句测试 + 主语测试过得去，不是一行一件的分镜表
- [ ] 有 ≥ 1 个当代生活物件；通用意象都加了限定
- [ ] **有一句"只有这个人会说"的话**；句长有毛边，不是全段等长
      （这一项优先级最高——它是"这里最值得改"的信号，不是判合格的条件）

**结构与句数（怀疑"结构不对"时查，第三节）**
- [ ] **不是每段都 4 句** —— 句数按实际 BPM 与情绪功能算出，不是默认取最小值
- [ ] 全首落在 2:00–3:30（用实际 BPM 算）；**副歌够不够，按时长看，不按句数看**
- [ ] 副歌秒数超 22 秒时**已经处理过**（减句 / 转重复）——22 秒是软上限，T4 末次副歌 22.6 秒也成立，
      所以"超 22 秒"本身不是错，放着不管才是错
- [ ] **主歌与副歌句数有差异**
- [ ] **副歌没吃掉整首歌**：副歌总时长 ≤ 全首 40%（卡点模板 ≤ 50%），次数 ≤ 4
- [ ] **模板理由与实际结构一致**：说"末次加长"就真的加长了，不能两头挂着
- [ ] 副歌 ≥ 3 次时，有一处爬升或留白（Pre-Chorus / 器乐段 / 抽空），不是副歌连着砸

**关于"及格线"**

只有开头那五条有及格线。**诊断表不设及格线** —— 它不是考试，是工具箱。
诊断表查出问题，按 `lyric-naturalness` 的改写流程处理；
其中**私人口吻**（"有没有一句只有这个人会说的话"）是优先级最高的信号，
但它不判不合格——它只是"这里最值得改"。

## 八、排版规范（严格遵守）

**歌词正文必须放在代码块里**，保证可一键复制、不被 markdown 折叠。

```
[Intro]

[Verse 1]
第一句歌词
第二句歌词
第三句歌词

[Chorus]
第一句歌词
第二句歌词
```

| 项 | 要求 |
| --- | --- |
| 结构标签 | 独占一行，英文，方括号包裹，**前后不加标点** |
| **每句歌词** | **独占一行，句与句之间不留空行** |
| 段落之间 | 空**一行**（且只空一行） |
| 句内断句 | 用**半角空格**分隔（"我买两支 买咗好耐"），不用标点，不用全角空格 |
| 演唱指示 | `[whisper]` `[falsetto]` 等单独成行，写在对应段落前 |
| 空段落 | 纯器乐段只写标签，标签后空一行，不写内容 |

> ⚠️ **不要每句之间都空一行** —— 那是段落格式不是歌词格式，复制进 Suno 会带一堆空行。

**交付文档结构**：

```markdown
# 歌词 ·《歌名》v1          ← 首版也写 v1，不设"首次不带版本号"的特例

> 上一版：outputs/{歌曲名}/…-v0-20260101.md    ← 首版写"无"

## 歌词                  ← 代码块，可直接复制

---
**一句话**：选了什么（模板 / BPM）、改了什么、哪里还不满意——**不超过 5 行**。
```

**就这些。** 用户要的是歌词，不是一份结案报告。

### 只有用户问了，才展开这些

| 用户问 | 你给 |
| --- | --- |
| "为什么这么定结构？" | 模板、实际 BPM 及来源、每段几句的理由 |
| "韵怎么押的？" | 韵辙 + 密度（主歌放开几句、放在哪） |
| "用了哪些意象？" | 意象词组矩阵 + 选韵理由 |
| "你自检了吗？" | 只列**没过的项**；全过就一句话 |

⚠️ **不许主动交这份「展开」**。实测七版里说明书占 61–69%，用户要翻过一整页辩护词才看得到歌词
（见 `AGENTS.md` 第 7 节「交付形态」）。

## 九、版本化与产出落盘

每首歌一个文件夹，歌词与提示词都放在里面：

```
outputs/{歌曲名}/
  {歌曲名}-lyrics-v1-20261030.md
  {歌曲名}-prompts-v1-20261030.md
  {歌曲名}-lyrics-v2-20261031.md
  ...
```

| 类型 | 文件名 |
| --- | --- |
| 歌词 | `outputs/{歌曲名}/{歌曲名}-lyrics-v{N}-YYYYMMDD.md` |
| 提示词 | `outputs/{歌曲名}/{歌曲名}-prompts-v{N}-YYYYMMDD.md` |

- **首版也写 v1**；歌词与提示词**各自独立递增**，版本号全局唯一，不重置、不回退、不复用
- 日期用**修改当天**（不是首版日期），放最后，同首歌的文件按「类型 + 版本」聚合排序
- 提示词文件头必须写明**对应哪一版歌词**（写路径），对应关系靠文件头表达，不靠文件名
  （不要把歌词版本号嵌进提示词文件名：迭代频率不对称，同一版歌词下可能有 prompts v1–v5，且嵌双版本号会出现两个 "prompts-v1"）
- **绝不覆盖原文件** —— 调整一律生成新文件：用户可能想回退、覆盖后无法 A/B 对比、版本链本身就是创作记录
- 新版本写明：**改了什么**（逐项对照）+ **上一版路径** + **为什么**。
  **不再要求写"没改什么""考虑过但没采用"** —— 那是自我辩护的格式，
  改一句词不该产出一份案卷（实测里模型为凑齐这几项，常把"未采用方案"写成充数段落）

**顺便**：每轮对话在 `outputs/{歌曲名}/{歌曲名}-log.md` **追加两行**（用户说了什么 / 你做了什么），

# 中文歌词创作

## 铁律

1. **结构标签一律英文**，用 Suno 通用格式。标签内不写中文。
2. 歌词是**唱**的，不是读的。每写完一段，默念一遍，拗口就重写。
3. 押韵服务于情绪，不为押韵造废句。宁可破韵，不要写"我的心/你的人"这种填充。

---

## 一、结构标签库（Suno 通用）

**完整标签表（含常用度、元标签、演唱指示）见 `references/suno-tags.md` 第一节** ——
那是唯一来源，中英文两个 skill 都从那里取，不要在 skill 里另存一份。

写词时只需记住三条：

1. **结构标签一律英文、方括号、独占一行**：`[Intro]` `[Verse]` `[Pre-Chorus]`
   `[Chorus]` `[Post-Chorus]` `[Bridge]` `[Instrumental Break]` `[Outro]` `[End]`
2. **`[Breakdown]` `[Drop]` `[whisper]` `[falsetto]` 是编曲事件的落点**，不只是结构标记
   （Suno 的 Style 字段读不懂长句，事件只能落在歌词标签里）
3. **纯器乐段只写标签**，不写说明文字

### 怎么选（**不要挑眼熟的那个**）

摆 9 个模板让 AI 挑，它会挑第一个 —— 跟"给范围不给规则就取最小值"是同一类病。按四步收敛：

1. **目标时长**：60–90 秒 → 只有 T5；2:00–3:30 → 其余
2. **谁是主体**：副歌是主体（抒情/宣泄）→ T1/T4/T9；主歌是主体（叙事/说唱）→ T3/T6；平衡 → T2；器乐是主体 → T8
3. **副歌几次、要不要变奏**：三次递进 → 6 句；末次要爆发 → 末次加长到 8 句（T4）；只回扣标题 → 4 句
4. **风格特例**：古风长句 → T7；电子舞曲 → T8；R&B → T9；说唱 → T6

**可选段落不要默认全加**：Pre-Chorus 在 T4/T3/T5 可省；Bridge 在 T5/T6 可用器乐间奏代替；
`[Instrumental Break]` 是编曲事件的载体，需要 solo 或抽空对比时才加。

### 模板给什么、不给什么

| 模板给 | 模板不给 |
| --- | --- |
| 有哪些段落、顺序、重复几次 | 句数（随 BPM 变） |
| 可选段落去留建议 | BPM（随用户要求变） |
| 典型 BPM 作**默认值** | 全首时长（随实际 BPM 变） |

**裁决规则与句数重算方法见第四节**（那里有 120 BPM 的实测案例与解法）。

选完要向用户说明**为什么选这套**。

## 三、十三辙押韵体系

中文歌词押韵以**十三辙**为准（详见 `references/rhyme-zh.md` 完整韵字表）。

| 辙名 | 韵母 | 情绪倾向 | 例字 |
| --- | --- | --- | --- |
| 发花 | a ia ua | 明亮、开阔 | 花 家 话 下 沙 芽 霞 |
| 梭波 | o e uo | 沉稳、叙述 | 河 火 我 说 破 过 朵 |
| 乜斜 | ie üe | 婉转、清冷 | 月 雪 夜 谢 别 街 蝶 |
| 一七 | i ü er | 细腻、私密、易密韵 | 期 你 意 里 雨 去 句 |
| 姑苏 | u | 低沉、呜咽 | 路 湖 树 苦 雾 孤 渡 |
| 怀来 | ai uai | 舒展、叹息 | 来 开 海 爱 外 待 快 |
| 灰堆 | ei ui | 柔婉、回落 | 悲 飞 水 泪 回 灰 醉 |
| 遥条 | ao iao | 悠远、飘逸 | 高 老 笑 道 草 桥 照 |
| 由求 | ou iu | 忧郁、绵长 | 愁 秋 留 手 头 酒 旧 |
| 言前 | an ian uan | 开阔、舒展、最常用 | 前 天 年 面 见 远 山 |
| 人辰 | en in un | 深沉、内敛 | 心 深 真 门 春 云 沉 |
| 江阳 | ang iang uang | 昂扬、宏大 | 光 长 方 上 乡 唱 望 |
| 中东 | eng ing ong | 浑厚、共鸣强 | 风 梦 中 空 声 影 情 |

### 选韵原则

- **开口度配情绪**：激昂用江阳/言前/发花（开口大）；低回用一七/姑苏/由求（开口小）
- **副歌固定一韵**，主歌可换韵制造对比
- **避免通押过头**：言前与人辰（-an / -en）可通押但慎用，容易糊
- **"一七辙"最易也最险**：字多好押，但容易写得绵软无骨
- **仄声韵**（三四声）比平声更有推进力和颗粒感，说唱和摇滚常用

### 韵脚位置

- **句尾韵**（默认）：每句/隔句末字同辙
- **句中韵**：句中顿挫处押，增加密度（说唱常用）
- **双押/三押**：末尾连续 2–3 字同韵（说唱）
- **转韵**：段落切换时换辙，标记情绪转折

## 四、结构与句数决策（**不要一律 4 句**）

### ⚠️ 常见错误

**给范围不给选择规则，模型就会默认取最小值。** 结果就是每段都是 4 句——
全首只有 1:38（比标准流行歌短三分之一），副歌每次 11 秒就走了，**情绪根本堆不起来**；
而且段落句数全相等，是结构层面的"AI 对称"。

**句数是算出来的，不是拍脑袋定的。**

### 决策流程（四步）

> 所有速查表、模板库、换算表都在 **`references/song-structure.md`**（唯一事实源）。
> 本节只给流程与硬约束 —— 定句数时**必须去读那个文件的对应节**，不要凭印象。
> 下表「查哪里」一律指 **`references/song-structure.md`** 的节号。

| 步 | 做什么 | 查哪里（`song-structure.md`） |
| --- | --- | --- |
| ① 选模板 | 按四步收敛取 T1–T9，**不要挑眼熟的那个** | 第七节 |
| ② 定 BPM | 用户说了用用户的；没说取模板典型值**并声明** | 第八节 |
| ③ 算句数 | `单句秒数 ≈ 240 ÷ 实际 BPM`；副歌再按情绪功能取下限 | 第二、四节 |
| ④ 校验 | 副歌时长、全首时长、段落句数关系 | 第二、五、八节 |

### 三条硬约束

**① 模板只给骨架，句数必须按实际 BPM 重算。**
模板表里的句数是该模板**典型 BPM 下的值**，不是定值。
实测：照抄 T2 副歌 6 句 + 120 BPM = 12 秒，掉出下限。
⚠️ **校验也要用实际 BPM** —— 用模板的 95 BPM 去校验会算出 15.2 秒「合格」，是假绿灯。
120 BPM 的解法是 **8 句 + `[Post-Chorus]` 尾缀**，不是 9 句（9 句副歌对流行歌偏长）。
主歌一般不用动：6 句在 70–140 BPM 全程都落在 10–20 秒区间内。

**② 副歌 15–22 秒、全首 2:00–3:30 —— 但两个约束不对称。**
- **句数下限是硬的**：堆积型 6–8 句、一击即中 4 句、需三次变奏 6 句
  （完整表见 `references/song-structure.md` 第四节）
- **秒数下限是软的**：15 秒是按 85 BPM 量体裁的经验值。BPM 高时**保句数、不保秒数**，
  减句数凑秒数会伤信息量，是往错误方向修。补时长用 `[Post-Chorus]` 或增加重复次数
- 叙事点缀型副歌（民谣、说唱）可短至 10 秒，靠出现次数建立记忆

**③ 句数关系按「功能」判断，不按位置。**
- **同功能重复段必须相等**（V1=V2、C1=C2、PC1=PC2）—— 同旋律，不等就唱不了
- **主歌 ↔ 预副歌 ↔ 副歌要有差异** —— 全首同句数是结构层面的"AI 对称"
- 桥段 / 尾奏可与上述同长（一次性段落，旋律本来就不同）
- ⚠️ 别写成"相邻段落句数不要相等"——照它执行会把 V1、V2 写成不同句数

### 单句字数与对齐

| 段落 | 单句字数 |
| --- | --- |
| Verse / Chorus | 7–11 / 7–12 字 |
| Pre-Chorus / Outro | 5–8 / 3–7 字 |
| **长句风格**（古风 / 氛围） | **12–16 字**（一句占 2 小节，句数相应减少） |

**对齐规则**：同段落内对应句字数差 ≤ 2 字。差太多唱不了。
**长句风格改按总字数校验**：副歌 30–60 字（真正约束是总时长，不是句数）。

**交付时必须写明**：选了哪个模板（T1–T9）、为什么；**实际 BPM 是多少、来源**（用户指定 / 模板默认值）；
每段几句、为什么这个句数（实际 BPM + 情绪功能 + 时长校验）；
**若实际 BPM 与模板典型值不同，写明句数相对模板做了什么调整**。

## 五、写作流程

```
① 提炼立意（一句话，具体到场景，不是抽象情绪词）
② 定 BPM（用户说了用用户的；没说取模板典型值并声明——它决定句数）
③ 选模板（T1–T9，按第 2 节四步，**只取骨架**）+ 定句数：
   按第 4 节（实际 BPM 倒推 → 情绪功能 → 段落差异）
   ⚠️ 实际 BPM ≠ 模板典型值 → 副歌重算，不照抄模板句数
   输出一张表：选了哪个模板、实际 BPM 及来源、每段几句、目标时长、为什么
④ 选韵辙（副歌定死，主歌可选另一辙）
⑤ 调 lyric-imagery-rhyme 取意象词组与押韵候选字
⑥ 写主歌（铺陈，给画面，不抒情）
⑦ 写预副歌（短句，情绪爬升）
⑧ 写副歌（hook 句首，按定好的句数写，留变奏位）
⑨ 写桥段（换视角/换韵，说一句最真心的话）
⑩ 写尾奏（渐弱，留白）
⑪ 自检（含句数与时长校验）
```

**主歌与副歌的分工**：
- 主歌 = **给画面**（具象名词 + 动作），不评判
- 副歌 = **给态度**（抒情 + 重复），是唯一允许直白的地方
- 桥段 = **给转折**（换个说法说同一件事，或说出主歌副歌都没说的那句）

## 六、中文歌词的常见坑

| 坑 | 症状 | 解法 |
| --- | --- | --- |
| 文言倒装 | "繁花落尽处"式生硬 | 改成口语能说的话："花都落完了" |
| 抽象词堆叠 | 孤独、寂寞、忧伤、彷徨连用 | 换成具象：空椅子、未接来电、凉掉的茶 |
| 韵脚陈词 | 心/人/情/梦/痛 反复出现 | 换辙，或用 `lyric-imagery-rhyme` 找同辙的冷门字 |
| 字数失控 | 一句 5 字一句 14 字 | 按段落字数表重写 |
| 副歌无 hook | 每句都新，没有重复 | 把核心句提到句首并重复 2–3 次 |
| 人称混乱 | 一段"我"一段"你"一段"他" | 通篇统一，桥段才允许切换 |

## 七、自然度红线（创作期预防）

**AI 味的病根是"平均化"** —— 写出来的东西所有人都能写，那它就谁也不属于。
取材阶段就要守住，别等写完再补救。

- **取材三问**：能被镜头拍到吗？换到另一首歌还成立吗？有没有一个细节是别人写不出来的？
- **每段主歌 ≥ 3 个具象名词**；全首抽象情绪词 ≤ 3 个
- **全首 ≥ 1 个当代生活物件**：电量 12%、外卖备注、已读不回、末班车、快递柜
- **通用意象必须加限定**：不写"雨"，写"把伞吹翻的雨"
- **句长要有毛边**：前几句保持对齐，**允许 1 句（通常是段落末句）明显更长或更短**做落句。不要全段等长（假），也不要全段乱（唱不了）
- **情绪越重，用词越轻**：不写"想你想到流泪"，写"牙刷还在杯子里"

替换词查 `references/anti-ai-lexicon.md`；完整法则与改写流程见 `skills/lyric-naturalness/SKILL.md`。

## 九、排版规范（交付格式，严格遵守）

### 歌词正文

**必须放在代码块里**（``` 包裹），保证可一键复制、不被 markdown 折叠。

```
[Intro]

[Verse 1]
第一句歌词
第二句歌词
第三句歌词

[Chorus]
第一句歌词
第二句歌词
```

**规则**：

| 项 | 要求 |
| --- | --- |
| 结构标签 | 独占一行，英文，方括号包裹，**前后不加标点** |
| **每句歌词** | **独占一行，句与句之间不留空行** |
| 段落之间 | 空**一行**（且只空一行） |
| 句内断句 | 用**半角空格**分隔（"我买两支 买咗好耐"），不用标点，不用全角空格 |
| 演唱指示 | `[whisper]` `[falsetto]` 等单独成行，写在对应段落前 |
| 空段落 | 纯器乐段落（如 `[Intro]` `[Instrumental Break]`）只写标签，标签后空一行，不写内容 |

> ⚠️ **不要每句之间都空一行** —— 那是段落格式不是歌词格式，复制进 Suno 会带一堆空行。
> ⚠️ 句内换行用空格，不要用逗号或句号（除非是刻意的语气停顿）。

## 一、歌词              ← 代码块，可直接复制

## 十、版本化与产出落盘

### 目录结构

每首歌一个文件夹，歌词与提示词都放在里面：

```
outputs/{歌曲名}/
  {歌曲名}-lyrics-v1-20261030.md
  {歌曲名}-prompts-v1-20261030.md
  {歌曲名}-lyrics-v2-20261031.md
  ...
```

### 命名规则

| 类型 | 文件名 |
| --- | --- |
| 歌词 | `outputs/{歌曲名}/{歌曲名}-lyrics-v{N}-YYYYMMDD.md` |
| 提示词 | `outputs/{歌曲名}/{歌曲名}-prompts-v{N}-YYYYMMDD.md` |

- **首版也写 v1** —— 规则统一，不用记"首次不带版本号"的特例
- 歌词与提示词**各自独立递增**，版本号全局唯一，**不重置、不回退、不复用**
- 日期用**修改当天**，不是首版日期；日期放最后，同首歌的文件按「类型 + 版本」聚合排序
- 提示词文件头必须写明**对应哪一版歌词**（写路径），对应关系靠交叉引用表达，不靠文件名

> 不要把歌词版本号嵌进提示词文件名（如 `-lyrics-v1-prompts-v1-`）。
> 迭代频率不对称（调 BPM、换音色不动词，同一版歌词下可能有 prompts v1–v5），
> 且歌词改措辞时提示词往往不用动 —— 只有歌词**结构**变了才需要新建提示词。
> 嵌双版本号还会出现两个 "prompts-v1"，说版本号时必须带前缀才能消歧。

### 硬约束：绝不覆盖原文件

调整一律**生成新文件**，不在原文件上改。理由：

1. 迭代是试错过程，用户可能想回到上一版（"还是 v2 的副歌好"）
2. 覆盖后无法 A/B 对比
3. 版本链本身就是这首歌的创作记录

### 新版本文件必须写明

- 相对上一版**改了什么**（逐项对照表最好）
- **上一版的文件路径**
- **没改什么**（明确哪些段落沿用，避免用户误以为全首重写了）
- **为什么这么改**，以及**考虑过但没采用**的方案及理由

（后两项很重要：用户常问"为什么不加 Post-Chorus""为什么不是 8 句"。）

文件头与「改了什么 / 没改什么」对照表的写法范本见 `examples/002-versioning.md`。
（`outputs/` 不进版本库，skill 里**不要引用**其中的具体文件——clone 后必然断链。）

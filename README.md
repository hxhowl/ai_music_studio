# AI Music Studio

人机协作写歌工作台。你给一段描述，它产出**规范化歌词** + **Suno / 秒响生成提示词（中英双语）**，并陪你迭代。

---

## 这份文档给谁看

| 文件 | 读者 | 作用 |
| --- | --- | --- |
| `README.md`（本文件） | **人** | 怎么使用、怎么唤起角色、怎么维护 |
| `AGENTS.md` | **AI** | 会话对齐入口：角色边界、skill 清单、硬性约定 |

两个文件不重复。唤起方式只写在本文，AI 该怎么做只写在 AGENTS.md。

## 三十秒理解

```
用户描述
   ↓
① AI 歌词助手（agents/ai-lyricist.md）
   ├─ 中文 → skills/lyric-zh
   ├─ 英文 → skills/lyric-en
   ├─ 卡韵 / 缺画面 → skills/lyric-imagery-rhyme
   └─ "太 AI 了" → skills/lyric-naturalness
   ↓ 产出：带 Suno 英文结构标签的歌词
② AI 歌曲生成助手（agents/ai-song-producer.md）
   ├─ skills/song-prompt-builder → Suno 英文标签串 + 秒响中文长句，各配中英说明
   └─ "都一个样" → skills/production-antislop
   ↓
③ 迭代：定向修改，不整首重写
```

## 如何使用

### 1. 开新会话

在**这个项目目录**下开新会话（工作区 = `ai_music_studio`）。会话启动时 `AGENTS.md` 自动进入上下文，技能列表里出现 8 个可用技能：

`ai-lyricist`、`ai-song-producer`、`lyric-zh`、`lyric-en`、`lyric-imagery-rhyme`、`lyric-naturalness`、`song-prompt-builder`、`production-antislop`

### 2. 唤起角色：三种方式

**① 说人话（最常用）**

不用记名字，直接说你要什么，AI 按意图自动匹配：

| 你想做的事 | 直接这么说 |
| --- | --- |
| 从零写一首歌 | "想做一首关于深夜地铁站的歌，女生唱，清冷一点但结尾要有希望" |
| 只要歌词 | "帮我写一段副歌，主题是异地恋，押中东辙" |
| 改已有歌词 | "这句不顺""韵脚太普通，换一个""副歌不够抓耳" |
| 找意象 / 押韵字 | "给我一些深夜城市相关的意象""一七辙能押哪些字" |
| 只要提示词 | "给这段歌写 Suno 提示词""秒响要怎么写" |
| 调整生成结果 | "编曲太素了""人声不对，想要气声""BPM 太快" |
| 歌词太 AI / 太啰嗦 | "这段太 AI 了""不够自然""像模板""没画面""像作文""太水" |
| 出歌雷同 | "出来的歌都一个样""太套路""没特点""像别人的歌" |

**② 点名角色**

自动匹配没触发、或想明确切换角色时，直接点名：

```
@AI 歌词助手  帮我把这段歌词改成古风
@AI 歌曲生成助手  给这首歌配器，出 Suno 和秒响的提示词
```

说"用歌词助手""交给作曲那个角色"也一样认。

**③ 指定 skill**

想绕过角色判断、直接走某条流程：

```
用 lyric-zh 写一首民谣
用 song-prompt-builder 给这段风格出提示词
用 lyric-imagery-rhyme 找押韵字
```

### 3. 两个角色怎么配合

| 你的诉求 | 会发生什么 |
| --- | --- |
| 只说写词 | 只走 AI 歌词助手，不碰提示词 |
| 只说编曲 / 提示词 | 只走 AI 歌曲生成助手，不碰歌词 |
| "帮我把这段描述做成一首歌" | **串行**：先出词 → 再出提示词 |
| 先要词、后来又要提示词 | 作词交付时会主动问要不要转给作曲 |

### 4. 如果角色没被自动唤起

新会话里先说这一句，把项目上下文拉起来：

```
先读一下 AGENTS.md，然后按里面的角色分工来
```

之后正常说需求即可。这句在技能未自动加载时同样有效 —— AGENTS.md 里写明了每个 skill 的文件路径，AI 会直接去读。

### 5. 首次使用，验证一下

新开一个会话，确认技能列表里有那 8 项。如果没出现，说明当前版本的技能发现路径不是 `skills/` 或 `.workbuddy/skills/`，需要换到 `~/.workbuddy/skills/`（但那就跨项目生效了，与本项目的"仅项目内"约定冲突）。

## 两个角色

| 角色 | 管什么 | 不管什么 |
| --- | --- | --- |
| **AI 歌词助手** | 立意、结构、意象、押韵、节奏、可唱性 | 编曲、音色、BPM 数值、人声设定 |
| **AI 歌曲生成助手** | 乐器编排、人声演唱、曲风、速度、调性、制作质感 | 写词、改词、找韵脚 |

一句话仲裁：**说"这句不顺"归作词，说"编曲太素"归作曲。**

## 全部条件只有 11 条（`AGENTS.md` 第 4 节）

判据是「**能不能机械判定**」。能机械判定的结果才当条件，其余全是参考材料。

> **条件只在 `AGENTS.md` 第 4 节定义**，各个 skill 只引用不复述。下面是**给人看的摘要**——
> 两边不一致时，**以 `AGENTS.md` 为准**（这份摘要的唯一作用是你不用读 AI 文档也能知道有哪 11 条）。

**通用**

1. **版本化**：每首歌一个文件夹，**调整一律生成新文件**，绝不覆盖上一版（迭代是试错，你可能想回退）

**作词侧（核对 1–5）**

2. **结构标签一律英文**：`[Verse]` `[Chorus]` `[Bridge]`，中文歌词也一样
3. **歌词排版**：正文放代码块，**一句一行，句间不留空行**，段落间空一行
4. **同功能重复段句数相等**（V1=V2、C1=C2）—— 同旋律，句数不等唱不了
   （**时长不在此列**：它随风格走，见下面「其余一切」）
5. **能唱**：没有歌手名、生僻字；品牌名可当具体物件，但不能进 hook

**提示词侧（核对 1、6–11）**

6. **Suno 硬限制**：≤15 个标签、≤200 字符（超了发不出去）
7. **主风格唯一 + 辅助 ≤1**，不出现自相矛盾的组合
8. **乐器 3–5 件，每件带演奏法或器材**（写 `brush snare`，不写 `drums`）
9. **人声三件套**：音区 + 音色 + 唱法
10. **质感至少两项**：年代 / 录音方式 / 空间与介质
11. **Exclude 非空 + 提示词中英双语**：Suno 英文标签串、秒响中文长句，**两者不互译**；
    每个平台配一行另一语言的说明

**交付形态**：默认只给**成果 + ≤5 行话**。结构说明、押韵表、意象表、定参表、逐标签解释、自检——**等你问了再展开**。

> **其余一切（字数、押韵密度、hook、具象名词、整体弧线、编曲锚点……）都是参考，不是门槛。**
> 想写得更好时去查 `AGENTS.md` 第 5 节那张表；写顺了就不用看。
> 阈值一多，模型就只顾着压字数、凑名词个数，甚至为凑押韵把全首最好的一句改坏。

## 交付物命名

每首歌一个文件夹，歌词与提示词都放里面：

```
outputs/{歌曲名}/
  {歌曲名}-lyrics-v1-20261030.md
  {歌曲名}-prompts-v1-20261030.md
  {歌曲名}-lyrics-v2-20261031.md     ← 调整后另存新文件，旧版保留
  {歌曲名}-log.md                    ← 对话留痕（追加写，见下）
```

| 类型 | 文件名 |
| --- | --- |
| 歌词 | `outputs/{歌曲名}/{歌曲名}-lyrics-v{N}-YYYYMMDD.md` |
| 提示词 | `outputs/{歌曲名}/{歌曲名}-prompts-v{N}-YYYYMMDD.md` |
| 对话留痕 | `outputs/{歌曲名}/{歌曲名}-log.md`（**追加写、不覆盖、不带版本号**） |

**对话留痕是干什么的**：你可能在 Trae 或别的客户端里跑这套流程，那些对话这边看不到。
每轮在 `log.md` 里追加两行（你说了什么 / AI 做了什么），下次迭代就能追溯"当时到底哪里不对"，
不用从产出反推。**它不记思考过程、不抄歌词、不算条件**（漏记不判错）。

- **首版也写 v1**，规则统一，不用记"首次不带版本号"的特例
- 歌词与提示词**各自独立递增**：调 BPM、换音色不动词，也算提示词新版
- 日期用**修改当天**；日期放最后，同首歌的文件按「类型 + 版本」聚合排序
- 新版本文件里要写明：**改了什么、上一版路径、为什么这么改**。（不用写"没改什么"——那是自我辩护的格式）
- 提示词开头写明对应哪一版歌词（写路径）—— 对应关系靠交叉引用，不嵌进文件名

> 为什么提示词不写成 `-lyrics-v1-prompts-v1-`：两者迭代频率不对称，且歌词改措辞时
> 提示词往往不用动（只有结构变了才需要新版）。嵌双版本号会出现两个 "prompts-v1"，
> 说版本号时必须带前缀才不产生歧义。

> `outputs/` 不进 git，是纯本地痕迹。想把某次产出留作样例，移进 `examples/`。

## 平台支持

- **Suno** — 英文标签串，≤15 标签 / ≤200 字符
- **秒响 Sway** — 中文长句，按九要素写（要素清单见 `references/platform-miaoxiang.md` 第二节，本文件不重复枚举）

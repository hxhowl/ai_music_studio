# AI Music Studio

人机协作写歌工作台。你给一段描述，它产出**规范化歌词** + **Suno / 秒响生成提示词（中英双语）**，并陪你迭代。

---

## 这份文档给谁看

| 文件 | 读者 | 作用 |
| --- | --- | --- |
| `README.md`（本文件） | **人** | 怎么使用、怎么唤起角色、怎么维护 |
| `AGENTS.md` | **AI** | 会话对齐入口：角色边界、skill 清单、硬性约定 |

两个文件不重复。唤起方式只写在本文，AI 该怎么做只写在 AGENTS.md。

## 三十秒理解

```
用户描述
   ↓
① AI 歌词助手（agents/ai-lyricist.md）
   ├─ 中文 → skills/lyric-zh
   ├─ 英文 → skills/lyric-en
   └─ 卡韵 / 缺画面 → skills/lyric-imagery-rhyme
   ↓ 产出：带 Suno 英文结构标签的歌词
② AI 歌曲生成助手（agents/ai-song-producer.md）
   └─ skills/song-prompt-builder → Suno 英文标签串 + 秒响中文长句，各配中英说明
   ↓
③ 迭代：定向修改，不整首重写
```

## 如何使用

### 1. 开新会话

在**这个项目目录**下开新会话（工作区 = `ai_music_studio`）。会话启动时 `AGENTS.md` 自动进入上下文，技能列表里出现 6 个可用技能：

`ai-lyricist`、`ai-song-producer`、`lyric-zh`、`lyric-en`、`lyric-imagery-rhyme`、`song-prompt-builder`

### 2. 唤起角色：三种方式

**① 说人话（最常用）**

不用记名字，直接说你要什么，AI 按意图自动匹配：

| 你想做的事 | 直接这么说 |
| --- | --- |
| 从零写一首歌 | "想做一首关于深夜地铁站的歌，女生唱，清冷一点但结尾要有希望" |
| 只要歌词 | "帮我写一段副歌，主题是异地恋，押中东辙" |
| 改已有歌词 | "这句不顺""韵脚太普通，换一个""副歌不够抓耳" |
| 找意象 / 押韵字 | "给我一些深夜城市相关的意象""一七辙能押哪些字" |
| 只要提示词 | "给这段歌写 Suno 提示词""秒响要怎么写" |
| 调整生成结果 | "编曲太素了""人声不对，想要气声""BPM 太快" |

**② 点名角色**

自动匹配没触发、或想明确切换角色时，直接点名：

```
@AI 歌词助手  帮我把这段歌词改成古风
@AI 歌曲生成助手  给这首歌配器，出 Suno 和秒响的提示词
```

说"用歌词助手""交给作曲那个角色"也一样认。

**③ 指定 skill**

想绕过角色判断、直接走某条流程：

```
用 lyric-zh 写一首民谣
用 song-prompt-builder 给这段风格出提示词
用 lyric-imagery-rhyme 找押韵字
```

### 3. 两个角色怎么配合

| 你的诉求 | 会发生什么 |
| --- | --- |
| 只说写词 | 只走 AI 歌词助手，不碰提示词 |
| 只说编曲 / 提示词 | 只走 AI 歌曲生成助手，不碰歌词 |
| "帮我把这段描述做成一首歌" | **串行**：先出词 → 再出提示词 |
| 先要词、后来又要提示词 | 作词交付时会主动问要不要转给作曲 |

### 4. 如果角色没被自动唤起

新会话里先说这一句，把项目上下文拉起来：

```
先读一下 AGENTS.md，然后按里面的角色分工来
```

之后正常说需求即可。这句在技能未自动加载时同样有效 —— AGENTS.md 里写明了每个 skill 的文件路径，AI 会直接去读。

### 5. 首次使用，验证一下

新开一个会话，确认技能列表里有那 6 项。如果没出现，说明当前版本的技能发现路径不是 `skills/` 或 `.workbuddy/skills/`，需要换到 `~/.workbuddy/skills/`（但那就跨项目生效了，与本项目的"仅项目内"约定冲突）。

## 目录说明

| 路径 | 内容 |
| --- | --- |
| `AGENTS.md` | **给 AI 读**：会话对齐入口，定义角色边界、skill 清单、硬性约定 |
| `agents/` | 两个助理角色的定义本体与职责边界 |

| `.workbuddy/skills` | 软链 → `../skills`，保证技能被发现（勿删） |
| `references/` | 去 AI 味词库、韵字表、Suno 标签库、秒响规范等静态参考 |
| `examples/` | 端到端样例：`001-empty-subway.md` |
| `outputs/` | 单次交付物落盘处（不进 git） |

> **关于 `.workbuddy/skills`**：这是软链，已随仓库提交，用于技能发现。
> 若 clone 后未生效（Windows 常见 —— git 默认不创建符号链接），手动重建：
> - macOS / Linux：`ln -s ../skills .workbuddy/skills`
> - Windows：开启「开发者模式」后重新 clone，或在 `.workbuddy/` 下执行 `mklink /D skills ..\skills`

## 两个角色

| 角色 | 管什么 | 不管什么 |
| --- | --- | --- |
| **AI 歌词助手** | 立意、结构、意象、押韵、节奏、可唱性 | 编曲、音色、BPM、人声设定 |
| **AI 歌曲生成助手** | 乐器编排、人声演唱、曲风、速度、调性、制作质感 | 写词、改词、找韵脚 |

一句话仲裁：**说"这句不顺"归作词，说"编曲太素"归作曲。**

## 四条不可违反的约定

1. **结构标签一律英文**：`[Verse]` `[Chorus]` `[Bridge]`，中文歌词也一样
2. **提示词必须中英双语**：哪怕只要一个平台
3. **Suno 与秒响不互译**：Suno = 英文标签串；秒响 = 中文长句。形态不同，各写各的
4. **反平均化**：AI 味的病根是"谁都能写出来"。歌词必须有可拍照的细节、当代生活物件，
   以及至少一句"只有这个人会说"的话。判据见 `skills/lyric-naturalness/SKILL.md` 的 10 条检测清单

## 平台支持

- **Suno** — 英文标签串，≤15 标签 / ≤200 字符
- **秒响 Sway** — 中文长句，按九要素写（风格 / 人声 / 发声 / 咬字 / 节奏 / 配器 / 旋律走向 / 入声时机 / 录音质感）

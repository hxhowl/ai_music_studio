# 示例 · 对话留痕怎么写

> ⚠️ **本文全是虚构的**，歌名、日期、用户的话都是编的，只用来演示格式。
> 不要把它当成某首歌的真实记录，也不要照着它去"补"任何一场已经过去的对话。
>
> 规则在 `references/logging.md`。本文件只演示**长什么样**，不重复规定。
> 实际文件放在 `outputs/{歌曲名}/{歌曲名}-log.md`（不进 git，只在本机）。

---

## 一、它长什么样

`outputs/示例歌/示例歌-log.md`：

```markdown
# 《示例歌》· 对话留痕

> 追加写，不覆盖。只记「用户说了什么 / 做了什么」，不记思考过程，不抄歌词。

## 2026-01-04

- **用户**：想要一首关于搬家整理旧物的歌，女声，别太煽情
- **AI**：出 v1（速度慢，中东辙）→ `示例歌-lyrics-v1-20260104.md`

- **用户**：主歌太满了，六句都在堆东西
- **AI**：v2 删到两件东西，只留纸箱和没撕干净的标签 → `示例歌-lyrics-v2-20260104.md`

## 2026-01-06

- **用户**：副歌记不住，听完想不起哪句
- **AI**：v2 副歌第三句提到句首做 hook，改 1 句 → `示例歌-lyrics-v3-20260106.md`

- **用户**：就这样。给我提示词
- **AI**：出词 v3 + 提示词 v1（Suno / 秒响）→ `示例歌-prompts-v1-20260106.md`
```

**一条一轮**：一次用户发言 + 一次回应。串行时（一句话里既出词又出提示词）仍然只记一条。

---

## 二、不该写进去的东西

对照上例，下面这些**都不要**：

| ❌ 别写 | 为什么 |
| --- | --- |
| 「我先算了主歌的句数够不够长，然后才动笔……」 | 那是**思考过程**。日志记事实，不记推理 |
| 把 v2 的完整歌词抄进来 | 版本文件里已经有了。抄一遍，两处就会开始漂移 |
| 「已核对条件 1–5，全部通过」 | 自检不进日志。它不是交付内容，也不是事实 |
| 「用户可能想要的是更克制的表达」 | 这是**你的推测**，不是用户说的话。推测一旦写进去，下次迭代会把它当事实读 |
| 把用户贴的一大段素材整段抄进来 | 超过 10 行的素材写「（贴了一段素材，约 N 行）」就够了，见 `references/logging.md` |

**唯一的原则：能指回原文的才写。** 指不回去的（推测、概括、事后评价），不写。

---

## 三、为什么不带版本号

版本文件是**快照**：`-lyrics-v2-` 就是那一刻的样子，改了就另存 v3。

日志是**一条线**：它记录的是"这首歌是怎么一步步变成现在这样的"。
如果也做 `log-v1` `log-v2`，每一份都得包含前面全部历史，只会重复三遍同样的内容。

所以它**刻意不参与版本号体系**：一个文件，一直往后追加。

---

## 四、和版本文件的分工

| | 版本文件 `-lyrics-vN-` | 对话留痕 `-log.md` |
| --- | --- | --- |
| 记什么 | **产物**：这一版长什么样、改了什么 | **过程**：谁提了什么、谁动了什么 |
| 读者 | 用户（要拿去用） | 下一次迭代（要追溯"当时为什么这么改"） |
| 形态 | 每版一个新文件 | 一个文件往后追加 |
| 缺了会怎样 | 无法回退、无法 A/B | 只能从产出反推，容易猜错 |

**两者不能互相替代**：版本文件看不出"用户当时到底不满意什么"，
日志也看不出"这一版的歌词具体是什么样"。

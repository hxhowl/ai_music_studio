# MEMORY.md · AI Music Studio 长期项目约定

## 项目是什么

人机协作写歌工作台。用户给自然语言描述 → 产出规范化歌词 + Suno/秒响生成提示词（中英双语）→ 迭代调整。

## 架构决策（用户已确认，不要擅自改）

1. **文件仅放项目内**，不安装到 `~/.workbuddy/skills/`。
2. **目标平台仅 Suno + 秒响（Sway）**，不扩展其它平台除非用户明确要求。

## 角色分工（硬边界）

- **AI 歌词助手**（`agents/ai-lyricist.md`）：立意、结构、意象、押韵、可唱性。**不碰**编曲/音色/BPM/人声。
- **AI 歌曲生成助手**（`agents/ai-song-producer.md`）：配器、人声、曲风、速度、调性、质感。**不碰**写词。
- 仲裁：说"这句不顺"归作词；说"编曲太素"归作曲。都要时**串行**（先出词再出提示词）。

## 硬性约定

- 结构标签一律 Suno 通用英文：`[Verse]` `[Pre-Chorus]` `[Chorus]` `[Bridge]` `[Outro]`
- 提示词恒出**中英双语**
- **Suno 与秒响不互译**：Suno = 英文标签串（≤15 标签、≤200 字符、1 主风格 + ≤1 辅、乐器 3–5 件）；秒响 = 中文长句九要素
- 不用歌手姓名代替风格
- 迭代是**定向修改**，不整首重写
- 交付物落盘 `outputs/YYYYMMDD-{歌曲名}-{lyrics|prompts}.md`

## 入口

新会话先读 `AGENTS.md`。细节在 `skills/` 与 `references/`。

## 如何使用（唤起角色）

- 在这个项目目录下开新会话即可，直接说人话，靠 skill 的 description 自动触发。
- 点名角色：`@AI 歌词助手` / `@AI 歌曲生成助手`。
- **兜底指令**（技能未自动加载时）：「先读一下 AGENTS.md，然后按里面的角色分工来」。
- 技能发现做了双路径兜底：`skills/`（工作区级）+ `.workbuddy/skills -> ../skills` 软链（项目级）。
  两个角色在 `skills/` 下是软链，本体仍在 `agents/`。**不要拆掉这个软链结构。**
- 触发能力几乎全靠 SKILL.md 的 `description` 字段，改正文不改 description 等于没改。

## 文档分工（用户明确要求，别混）

- **`README.md` 给人看**：怎么用、怎么唤起角色、怎么维护。
- **`AGENTS.md` 给 AI 看**：只写 AI 该怎么做（角色边界、硬性约定、skill 清单）。
- 唤起方式**只写 README**；AGENTS.md 第 3 节只保留「角色选择规则」三条（点名优先 /
  未点名按仲裁表 / 不复述使用说明）。两文件不重复。

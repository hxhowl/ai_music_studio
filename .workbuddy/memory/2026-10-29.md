# 2026-10-29

## 解决「新会话如何唤起角色」

用户问：新会话怎么用这个项目、怎么唤起两个角色。

### 查证到的 skill 发现机制（两个口径不一致）

- 腾讯云官方问答口径：优先级 `.agents/skills/` > `skills/`（工作区级）> `~/.workbuddy/skills/`
- 社区拆解文章口径（称拆解过系统提示词模板）：用户级 `~/.workbuddy/skills/`，项目级 `<项目>/.workbuddy/skills/`

实测：当前会话启动时 skills/ 还不存在，无法验证；`skill_management` 工具只覆盖用户级安装项，也验证不了。

### 因此做了双路径兜底（不牺牲「仅项目内」原则）

- `skills/ai-lyricist/SKILL.md` → 软链到 `agents/ai-lyricist.md`
- `skills/ai-song-producer/SKILL.md` → 软链到 `agents/ai-song-producer.md`
- `.workbuddy/skills` → 软链到 `../skills`

两个角色原本只是 `agents/` 下的定义文件，不进 skill 发现范围，无法被自动触发。改成软链进 `skills/` 后，靠 SKILL.md 的 description 触发。

### description 补强

角色文件的 frontmatter description 重写，塞入用户真正会说的原话（「AI 歌词助手」「写词」「找韵脚」「编曲太素」等），并互相指名对方划边界。description 是触发的唯一依据，这步比正文重要。

### 兜底指令

技能未自动加载时，用户说「先读一下 AGENTS.md，然后按里面的角色分工来」即可——AGENTS.md 里写明了每个 skill 的文件路径，AI 会直接 Read。

### 待验证

下次开新会话时确认技能列表是否出现 6 项（ai-lyricist / ai-song-producer / lyric-zh / lyric-en / lyric-imagery-rhyme / song-prompt-builder）。若未出现，说明两条路径都不生效，需改到 `~/.workbuddy/skills/`（但那违背用户「仅项目内」的选择，要先问）。
